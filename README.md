# 面向研究生的校园 AI 助手：ThesisFlow

## 一、项目定义与核心愿景

### 1.1 项目定义

ThesisFlow 聚焦研究生学术研究与校园生活核心场景，构建专属智能化信息处理工作流。

- Thesis（论文 / 文献）：代表对学术研究场景的深度专注。
- Flow（流 / 工作流）：象征将文献搜索、深度分析、创新启发到报告生成的全流程自动化、智能化，让科研与校园事务处理更高效顺畅。

### 1.2 定位

本项目旨在为研究生群体构建一个专属的 AI 助手，解决以下两大问题：

1. 学术研究的 “信息获取” 与 “创新想法”
   - 面对海量且快速增长的学术文献，研究生可能难以高效完成前沿追踪、深度阅读和观点整合，且有时候难以得出一些好的想法。
   - 所以我们想构建一个 “AI 协作者” ，自动化完成智能文献搜索、深度分析总结到创新思路启发的全流程，减轻研究生的负担。
2. 校园政策的 “查询不便”
   - 奖学金、毕业要求、实习规定等关键校园政策信息可能比较杂乱。
   - 所以我们想打造一个 “校园政策百事通” ，通过知识库整合校内官方信息源，为用户提供精准、一站式的政策问答服务。

## 二、对比现有大模型

1. 在获取文献的实时性上

   通用模型的知识库更新缓慢，无法获取最新研究成果。

   我们直连 Arxiv 等学术数据库，能实时追踪并分析最新发表的论文，确保提供的信息的时效性。

2. 在学术可信度上

   通用模型有 “文献幻觉” 的问题，常编造不存在的论文和结论。

   而我们的则 100% 基于真实论文进行分析，所有观点均有据可查，并提供原文链接供用户核验和阅读，保证了学术输出的可靠性。

3. 在信息整合上

   通用模型的输出多为松散的文本摘要，缺乏深度。

   我们则能生成结构化的深度研究报告，内嵌专业分析模块，使得提供的不是信息堆砌，而是有确切的学术洞察与研究思路的。

4. 在服务场景上

   通用模型无法接入特定院校的内部信息。

   我们创建校内信息知识库，能精准解答奖学金、毕业流程等具体问题，让 AI 融入日常校园生活。

### （一）学术研究流：从 “文献获取 - 深度分析 - 可信输出” 全闭环

- 信息获取模块：核心是**接入 Arxiv 搜索引擎**，通过配置.env 文件完成引擎对接。
- 深度分析模块：核心是改**造 DeerFlow 现有 reporter_node 逻辑**，不改动核心 planner_node 以保障规划器稳定，通过条件判断（启用 enable_deep_thinking 参数）接入更强的推理模型，并设计专属学术提示词模板。
- 可信输出模块：核心是生成结构化学术报告，**设计标准化模板**；强制要求报告中所有观点关**联 Arxiv 原文链接**，规避学术幻觉。

### （二）校园服务流：从 “知识构建 - 智能检索 - 精准输出” 全闭环

- 知识构建模块：利用 **RAGflow 搭建本校专属权威知识库**，整合奖学金、毕业要求、实习规定等官方政策文件；并定期同步学校官网，确保信息的时效性与权威性。
- 智能检索模块：由 **deerflow+ragflow** 原本已经实现的功能直接**复用**。
- 精准输出模块：直接**返回结构化答案**（含核心结论 + 政策原文引用 + 适用说明）；若查询内容未完全匹配知识库，则**提示 “建议参考学校官网最新通知”** 并提供对应链接，保障信息严谨性。

### （三）统一支撑层

统一支撑层是系统的公共能力基座，核心解决“两大工作流孤立”的问题，同时明确前端与后端调度的职责边界，避免职责混淆，让架构设计更清晰：

- 前端交互支撑：基于 DeerFlow 前端框架改造，将标题与品牌标识更新为 “ThesisFlow”；交互规则设计为 “用 @+ 知识库，不用则默认启用文献搜索、总结及分析功能”。
- 智能路由调度支撑，Coordinator 与 Planner：作为后端核心调度枢纽，接收前端附带“查询类型标记”的请求（@），进行调度。

## 四、总结

总而言之，ThesisFlow 的核心价值在于 —— 从通用型 AI 助手转变为深度垂直于研究生学习与生活场景的专业伙伴，让研究生专注于最重要的创新思考，将繁琐的信息处理交给的 AI 协作者。

我们通过构建文献研究与校园服务双轮驱动的工作流，将 AI 能力无缝嵌入研究生科研学习的全流程：

- 在学术层面，我们让文献调研从耗时数周的手工劳动变为分钟级的自动化流程
- 在校园生活层面，我们让政策查询从碎片化的搜索变为一站式的智能服务
